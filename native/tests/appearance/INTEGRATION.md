# Appearance integration

The source-owned compositor orders system/custom wallpaper, procedural base, holiday scene, transparent overlay, then interactive content. Changing an overlay never changes the wallpaper or base fields. Selecting a procedural background explicitly clears the selected holiday scene. Selecting a wallpaper source retains separate background and overlay choices.

Register `appearance.BackgroundSettingsActivity` and `appearance.BackgroundPreviewActivity`. Link Appearance to the settings activity with the label `Backgrounds and overlays`. After creating Home content, retain `BackgroundLayer.attach(activity, content)` and call `setResumed(true/false)` from the owning activity's resume/pause. The compositor refreshes preferences on resume; repeated Home does not require recreating it. `refresh()` applies external changes while resumed.

`AppearancePreferences.FILE` is `source_appearance`. Base keys are `base`, `base_frozen`, `base_speed`, `base_intensity`, `base_brightness`, `base_palette`. Overlay keys are `overlay`, `overlay_frozen`, `overlay_speed`, `overlay_intensity`, `overlay_opacity`, `overlay_palette`. Numeric values accept 0 through 100 and default to 50. Effects default to Off, freeze flags default to false, palette ids default to empty. `scene` selects explicit holiday artwork. `wallpaper_image_uri` and `wallpaper_video_uri` retain both owner references; `wallpaper_mode` chooses system, image or video. Content URIs and canonical app-private file URIs can render. Arbitrary file/network references remain stored and fall back to the system wallpaper.

PaletteRecipes retains all 41 first-party maintained legacy color recipes. These are identified as palette recipes in the UI and are distinct from actual holiday scene artwork. Procedural effects are new source rendering and use shared families; preserving the style identities does not establish identical legacy pixels or owner visual acceptance.

Run `python3 native/tests/appearance/run.py` for host persistence checks. Appearance, holiday and instrumentation sources compile against the Android SDK in a temporary output directory. After the coordinator builds the combined preview, `python3 native/tests/appearance/build_native_test.py` prepares the native proof. Run `com.jeremykenedy.firetv.ui.appearanceproof/com.jeremykenedy.firetv.ui.nativeapp.appearance.AppearanceInstrumentation` only under an exclusive device lease. It exercises the actual Settings route, preview and Back, independent overlay callbacks with base Off, pause/still behavior, bitmap transparency and opacity. It restores and reads back all appearance preferences.

Prepared proof is not native execution. Physical wallpaper providers, owner media, video decoder behavior, target TV motion quality, gradient banding, performance and all style appearances need native review. No shared build output, manifest, Main, Pages, Settings, device or production installation was changed by this lane.
