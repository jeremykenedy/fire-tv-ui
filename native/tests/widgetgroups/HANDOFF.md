# Grouped legacy widgets

`WidgetGroups.decode(raw)` validates the observed nested group structure and preserves original per-record IDs, type, Big or Small size, arbitrary JSON data and additional fields. It retains empty groups and supports duplicate types. Unsupported records remain in the model and render as explicit unavailable entries. Weather retains the original location and unit and requires an explicit location selection before forecasting; selected settings are stored per record in `source_weather`. DigitalClock and YearProgress render only when their data is empty and no unknown record fields are present. The legacy Year Progress adapter draws a dot grid; visual parity and rounding beyond the observed November 2 fixture remain unverified.

`WidgetGroupMigration.patch(legacy, nativeLayout)` validates `widgets_config` and returns the exact original JSON as `native_layout/widget_groups`, including when `enable_widgets` is false. Absent configuration produces no patch. A conflicting existing grouped value rejects. This is a read-only preparation API: production migration intentionally does not yet call it or mark `widgets_config` resolved.

`WidgetGroupsStore` reads and updates only `native_layout/widget_groups`; it retains all other layout keys, checks the expected previous value and attempts rollback if a synchronous write fails. `WidgetGroups` supports group movement, replacement, removal and empty group insertion/removal without flattening UUIDs. `WidgetGroupsEditor` exposes these actions through a dialog, requiring explicit selection before replacing or removing an unavailable entry. Valid Weather records open a scoped settings activity by record ID; its compare and save rejects concurrent grouped layout changes.

`WidgetGroupsView(activity, groups, editor, widthDp, heightDp)` produces one horizontal column per saved group. Two Small records render stacked; a single Small renders a second Add widget slot. Each record has its own focusable view tagged with its saved UUID, with distinct provider instance and explicit unavailable fallback. The host must honor the saved widgets-disabled mode, create `WidgetGroupsEditor(activity, refreshCallback)`, call `start()` when Home is visible and `stop()` when hidden, then recreate or refresh the view after edits. Unknown entries are not silently discarded. Group positions are currently indexed and the owner must reconcile them with channel ordering and focus after edits.

Run `python3 native/tests/widgetgroups/run.py` for the host identity, round-trip, editing and migration checks, a simulated interrupted presentation-journal write and retry, plus Android API 36 compilation. Native layout, focus, edit interaction, provider lifecycle, on-device grouped recovery, actual 1.17 upgrade and physical TV acceptance remain unverified. Do not unblock `widgets_config` until Home integration, exact supported record behavior and recovery have been validated.
