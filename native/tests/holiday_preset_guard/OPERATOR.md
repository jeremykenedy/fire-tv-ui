# Holiday preset recovery proof

Synthetic production-package lab only. Use a fresh disposable emulator with the production package, guard package and proof package absent. Record baseline package inventory, Home and accessibility state. Verify candidate, provider-free seed, guard and proof have the same isolated review signer and that their exact SHA-256 values match the build receipts. Do not touch a real installation or a physical TV.

Build the fixtures from the repository root against the exact frozen candidate classes and the same isolated review keystore (alias `candidate-review`, password `android`):

```
python3 native/tests/holiday_preset_guard/seed/build.py --keystore /path/to/review.jks
python3 native/tests/holiday_preset_guard/proof/build.py --candidate-classes /path/to/frozen/classes --keystore /path/to/review.jks
```

Record the hashes and signer output alongside the candidate and guard receipts. Build in an isolated checkout with a clean fixture `.build` directory. The scripts use Android SDK platform 36 and build-tools 36.0.0 under `~/Library/Android/sdk`.

1. Install the provider-free seed APK. Run `com.jeremykenedy.firetv.ui/com.jeremykenedy.firetv.ui.seed.SeedInstrumentation`; require RESULT_OK and its synthetic seed PASS. The fixture refuses nonempty app data roots and plants a partial three-store preset, a valid affected-key recovery journal and a completed startup marker. Force-stop the lab.
2. Install the same-signer production-target state-guard proof and holiday proof. Capture and verify a durable guard with explicit `shared_prefs,files,no_backup` roots, `quiescent=true`, a unique case ID and an empty Android keystore. Record the exact manifest hash and immutable preupgrade verify receipt SHA-256. Do not launch the candidate before capture and verify succeed.
3. Replace the seed with the reviewed production-package candidate using `install -r` only after verifying package, version and signer. Its real provider startup runs the gate. Run `com.jeremykenedy.firetv.ui.holidaypresetproof/com.jeremykenedy.firetv.ui.nativeapp.migration.HolidayPresetInstrumentation` with `state_guard_case_id`, `state_guard_manifest_sha256`, and `preupgrade_receipt_sha256`. Require RESULT_OK and the exact PASS. The proof verifies restored typed values and absence after provider-started recovery; creates a synthetic corrupt pending journal while the editor is open; verifies affected getters and readiness block; triggers an editor action and checks redirect to Retry; verifies failed Retry retains data; then replaces only its synthetic journal with a valid fixture and verifies same-process Retry restores the prior values.
4. With the same guard still retained, run `com.jeremykenedy.firetv.ui.holidaypresetproof/com.jeremykenedy.firetv.ui.nativeapp.migration.HolidayThemeUiInstrumentation` using the same guard and receipt arguments. Require RESULT_OK and its exact PASS. It exercises the actual Hanukkah chooser and Apply, checks the selected base, preserved overlay/wallpaper, coordinated focus and icon plate pixels, and leaves Home visible for the operator to capture a screenshot. If instrumentation returns to another foreground app, explicitly reopen the candidate Home and wait for it to settle before capturing and inspecting that screenshot. On failure, save the reported private `failure_screenshot` before cleanup, if available. This is one UI case, not acceptance of all themes.
5. Force-stop the candidate. Replace it with the same provider-free seed APK before any guard restore, verify package/version/signer and force-stop again. Run guard restore, verify and resolve with the original case ID, manifest hash, roots and quiescent flag. Require exact match and verified resolution. If any guard, package replacement or readback fails, stop and retain the lab and guard for review. Only after successful restoration remove the synthetic packages and verify the original emulator baseline.

The seed and proof APKs built here use the isolated review signer. The proof must be rebuilt against the frozen candidate classes and same signer before the operator runs it. No production release, existing installation, physical TV or global setting is part of this proof. The fixture does not test visual holiday icon parity or a real in-place upgrade.
