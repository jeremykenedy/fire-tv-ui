# Sleep and protection lane

Register `com.jeremykenedy.firetv.ui.nativeapp.device.protection.ProtectionActivity` as a non-exported activity. Suggested Settings button: `Sleep and protection`. No boot receiver, service, job or privileged grant is required. The optional direct system sleep-timeout editor requires a WRITE_SECURE_SETTINGS manifest declaration and an existing TV grant; the module never requests or obtains that privileged grant itself.

The implemented option is explicitly limited to keeping Home's visible view awake. It defaults to off without writing a preference during startup. Enabling requires confirmation explaining that a system screensaver may be suppressed while Home is visible. Turning it off follows the existing system behavior. There is no wake lock, timeout write or effect on another app.

If approved for integration, Main owns one `LauncherAwakeController(getWindow().getDecorView())` instance. Call `onResume(this)` when Main resumes, and `onPause()` when it pauses. The controller restores the view's earlier request when releasing its own request. Do not apply it to every Activity or a background service.

SleepStatus reads the exact reported screen-off timeout, secure sleep timeout and Fire OS Alexa auto-wake value. Missing, negative, zero and malformed values stay distinct. It never substitutes a timer default. TV system settings handoff uses the existing DeviceRoutes capability and durable Home exemption.

The optional explicit system sleep-timeout editor only supports an already reported `sleep_timeout` value with existing WRITE_SECURE_SETTINGS permission. It accepts 1 to 35791 positive whole minutes after a user confirmation explaining the whole-device effect. It reads the new value back before reporting success. Failed partial writes restore the exact previous value; an intervening owner/system change is preserved and reported as requiring inspection. There is no automatic enforcement, default timer write or saved desired value. The shared screensaver timer `screen_off_timeout` remains owned by ScreensaverSystem and is only read here.

Legacy source review found automatic settings repair touching sleep, Alexa, receiver, ADB, Home and screensavers, plus a VPN updater blocker and a private Fire OS sleep-timer binder. None is reused here. This limited module does not fulfill legacy continuous settings protection, Fire OS Alexa deep-sleep toggles, one-shot Fire OS sleep timers or Amazon update blocking. Those remain explicit parity gaps rather than inert toggles.

Focused verification: `python3 native/tests/protection/run.py` compiles source against Android 36 in an isolated temporary directory and checks missing/default/zero/exact/malformed/overflow timer presentation, explicit write/readback, denied/missing capability, rollback and intervening changes. Native integration and physical sleep behavior remain unverified. No device, system settings, shared build, source commit or release was touched by this lane.

Native suite APK builds with `python3 native/tests/protection/build_native_test.py`. After the combined preview includes the route/Main controller hooks, the exclusive operator can install `.build/protection-proof.apk` and run `com.jeremykenedy.firetv.ui.protectionproof/com.jeremykenedy.firetv.ui.nativeapp.device.protection.ProtectionInstrumentation`. This exercises actual Main > Settings > Sleep and protection, default absence, canceled opt-in, explicit enable, Home request and leaving-Home release, then off. It snapshots/restores its exact app preference and checks the system sleep timeout remains untouched. It does not test an actual system timeout edit or hardware sleep timing. Native execution is still pending.
