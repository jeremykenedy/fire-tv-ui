# Sun and moon calculation provenance

This is an original Java implementation of published mathematical formulae. No inherited application bytecode, astronomy library, downloaded executable code, astronomical image or external runtime service is used. The original Java files fall under this repository's MIT license. ## Mathematical sources

Paul Schlyter, [How to compute planetary positions](https://stjarnhimlen.se/comp/ppcomp.html), sections 3 through 9 and 15, supplies the epoch, solar and lunar orbital elements, coordinate transforms, lunar perturbation terms and illumination geometry. His [worked tutorial](https://stjarnhimlen.se/comp/tutorial.html), sections 5, 7 and 8, supplies the independent 1990-04-19 numeric examples used by tests. The tutorial says "No programs are given". The inspected formula pages do not specify a software license. No license to any third-party software is asserted, and no program from those pages is distributed. The published mathematical relationships and numeric orbital coefficients are implemented in new Java source, with attribution here and in the calculation class.

The solar root solver, local civil-day selection, polar ambiguity handling, configuration, rendering and lifecycle code were written for this widget. Eccentric anomalies are solved with eight bounded Newton iterations; the published 12 lunar longitude and five latitude perturbation terms are retained. Lunar distance is not displayed or used. Illumination uses Schlyter's geocentric angular separation approximation, not a constant-length lunar-month shortcut. The result is displayed as approximate whole-percent illumination. Phase names near the main phases say "Near" and do not assert exact phase-event times.

The sunrise threshold is solar-center altitude -0.833 degrees, the conventional clear, sea-level horizon incorporating average refraction and apparent solar radius. The convention is documented by [NOAA's solar equations](https://gml.noaa.gov/grad/solcalc/solareqns.PDF). We do not copy NOAA's calculator code. [NOAA's disclaimer](https://gml.noaa.gov/about/disclaimer.html) states: "The information on government servers are in the public domain, unless specifically annotated otherwise". This implementation is not official NOAA output or endorsed by NOAA.

Solar altitude is searched through the configured local date in five-minute brackets and each detected crossing is bisected to below one second. This is numeric root resolution, not observational accuracy. DST uses a calendar-day increment rather than adding 24 hours. At high latitudes, days fully above or below the threshold get explicit polar descriptions. Days with one event, or no sampled crossing within 0.1 degrees of the threshold, are labeled polar-transition/unavailable instead of inventing a rise/set time. A very short grazing event may remain unresolved. Terrain, elevation, weather and variable refraction are not modeled.

Input dates are bounded to UTC 1901 through 2099, within the published century-scale domain. The displayed date and events use the explicitly configured IANA timezone. Manual coordinates are validated including finite-number checks; no automatic location permission, geocoder or network operation is used. These are approximate astronomical calculations and carry no medical claims.

## Independent reference data and measured limits

`usno-fixtures.json` contains six unmodified JSON responses from the [US Naval Observatory one-day data API](https://aa.usno.navy.mil/data/api). Each fixture retains its exact request URL, public sample coordinates and API version 4.0.1. No owner location is used. Responses contain event-time facts and whole-percent illuminated fractions; no photos or third-party application code are included. The API documentation does not provide a separate software license for these factual outputs; no license to a software package or image is implied.

The USNO API reports illuminated fraction at noon in the requested timezone. Tests compare that same instant. Four rise/set examples cover Greenwich equinox, New York autumn DST, Sydney winter solstice and Kiritimati date-line rollover. Two more verify Tromso polar summer and winter. The observed largest solar error in these four cases is 0.441 minutes; the largest illumination difference in the six cases is 0.376 percentage points. Automated tolerances are two minutes and one percentage point, respectively. These tests establish only those cases. They do not establish a universal numerical error bound across all supported dates and locations or prove observed sunrise under local atmospheric conditions.

[USNO's phase definitions](https://aa.usno.navy.mil/faq/moon_phases) distinguish phase events from illuminated fraction. This widget does not calculate moonrise/moonset, exact primary-phase events, visibility forecasts, eclipse predictions or daily astronomy images. The separate approved Daily astronomy source/image/cache backlog remains open.
