# Fire TV UI 1.20.1

This patch fixes four problems in the existing production interface: previous menus showing behind a settings window, unused wallpaper references blocking saved setups, stale release details during update checks, and blank cards when artwork is missing. Existing layouts, HD logos and appearance controls remain available.

## Upgrade guide

The direct upgrade source is stable 1.20.0/code 83. The update retains the production package and signing certificate and advances to code 84. Android API 27 remains the minimum. Save a launcher backup and keep selected personal media available before updating.

Use **Settings > Updates > Check for updates** and confirm the Android replacement, or verify the downloaded checksum and install in place:

```sh
shasum -a 256 -c fire-tv-ui-1.20.1.apk.sha256
adb -s YOUR_TV_IP:5555 install -r fire-tv-ui-1.20.1.apk
```

No new accounts, dependencies or preference reset are required. Do not uninstall to bypass a signing or version error. The independent preview is not an upgrade source. Earlier 1.x paths remain in their release guides.

Android normally blocks downgrading code 84 to code 83. Keep the installation for a corrective update; a preference backup does not downgrade the APK or restore external media and credentials.

## Breaking changes

None. Existing appearance choices, artwork, card controls, app focus growth and shadow remain. The independent replacement remains held and is not included. Mixed widgets and cards are not part of this patch.

## Major changes

This release contains repairs only. Optional presets and backgrounds introduced in 1.20.0 remain available with their existing defaults and saved choices.

## Minor changes and fixes

Menu windows cover the previous settings screen, so its heading no longer appears through the margins. Home wallpaper and selected menu backgrounds and overlays remain unchanged.

Named setups can save and apply a theme with an unused historical wallpaper reference. When the selected theme actually uses an image, a missing image still blocks the operation without changing the current setup. Retained image history is preserved.

Starting an update check clears the previous available version, result message and release details for affected apps. Pending details cannot be opened. Results and valid details return when the check completes; retrying one app retains other rows' results.

Cards with hidden titles show a readable feed or app label when their artwork is missing or fails to load. A duplicate feed subtitle is suppressed in that fallback state. Focusing the card retains its current title, and successful artwork keeps the original presentation. Artwork request state and callbacks follow the current image rather than an older request.

## Verification and limits

The maintenance build, standalone Java checks and host suite passed: 91 tests ran with six existing opt-in device checks skipped. Three current/historical maintenance recipe checks passed. Compared with public 1.20.0, 703 runtime entries are identical; only the manifest and two DEX files differ. All 48 original HD logos and all 50 icon ZIP entries are unchanged. No permissions were added.

The exact signed code 84 APK upgraded public 1.20.0 on two Android TV API 34 fixtures. The appearance lane retained all 43 captured typed preferences and all 14 private files, including the original custom HD image and Muted icon choices. The populated card lane retained all 21 exported preference values, canonical export bytes and all four synthetic provider rows. Public JSON export does not independently prove every Android storage type or private file.

Final native checks covered missing/failed artwork labels, current focused titles, successful artwork, card Menu/Back, named setup Save/Apply with an unused missing image, and ordinary Settings/App Icons/Backgrounds routes. Updates accurately reported installed 1.20.1 as newer than the then-published 1.20.0, cleared pending details, returned accurate cached details and restored the Updates row on Back. Both fixture guards and platform state were restored and verified; the test devices retained code 84 without uninstalling or downgrading.

The current gallery contains 18 unmodified captures from the exact signed code 84 APK. The README, current gallery and icon guide were rendered with GitHub Markdown and verified in a browser.

The scoped saved-setup checks covered actual Save and Apply with an unused missing wallpaper reference, active missing-image rejection, and preservation of the original settings. The Updates checks used the real published release, rechecked it, attempted the old details action while pending, opened valid cached details and verified Back/focus. That check did not install a downloaded release. The existing status summary can wrap to another line; no whole-page pixel stability claim is made.

Scoped artwork checks used synthetic local feeds. Missing and HTTP 404 artwork showed the feed label. In a continuous Home process, switching to a newer image while an older request remained pending retained the current image and episode title after the older request completed. Successful image pixels remained unchanged in the measured artwork region.

Default and 130% system text checks on public 1.20.0 found no clipping in the three-action appearance-preset dialog or maximum-length saved-setup name/actions. These unchanged controls required no separate text-layout repair. Those checks do not cover every screen or every text scale.

Home routing, soundbar control and external Plex playback/resume retain their existing limits. Native emulator checks do not establish physical remote latency, voice/CEC behavior, universal hardware performance or owner acceptance on every TV.
