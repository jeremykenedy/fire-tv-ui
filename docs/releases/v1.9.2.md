# Fire TV UI 1.9.2

Fix screensaver previews on Fire OS versions without the legacy SystemUI preview starter. The picker uses accessible app previews and clearly separates them from app-owned preview controls.

## Upgrade guide

Upgrade in place from 1.9.1 through **Preferences > Advanced > Updates**, or verify the published signed APK and use the repository installer:

```bash
shasum -a 256 -c fire-tv-ui-1.9.2.apk.sha256
python3 scripts/install.py --serial YOUR_TV_IP:5555 --apk /path/to/fire-tv-ui-1.9.2.apk
```

Older installed versions can use the same installer. Do not uninstall, clear data or reset the TV. Existing layout, icons, cards, approved encrypted Plex connections and screensaver settings remain intact. Android 8.1/API 27 remains the minimum. No new dependencies, permissions, migrations, account approval or cache reset are required. Save a launcher backup before upgrading. If installation fails, retain the existing app and inspect the error. Android can reject downgrades; use a corrective signed update instead of clearing app data.

## Breaking changes

None. This patch retains the production package, signer, runtime floor, defaults and saved preferences.

## Major changes

- **Preview it** opens a reviewed, accessible full-screen app preview without temporarily changing the system's selected screensaver.
- **Preview controls** opens the app's own accessible settings or launcher when its preview is private or missing. Choose Preview or Show aquarium inside the app, then use Back to return.
- Targets must belong to the selected screensaver's package and be enabled, exported and accessible to Fire TV UI.

## Minor changes and fixes

- Check that the system preview starter exists and is callable before attempting it. Some Fire OS builds do not include Somnambulator.
- Restore the original selection and enabled state after a failed system fallback, and retain recovery state if it cannot be saved.
- Keep the longer preview action labels centered on one line.
- Share safe app-settings resolution between Screensaver settings and Preview controls.
- Correct obsolete documentation about the launcher idle delay; the existing engine uses the configured TV delay and resets its inactivity period on Main resume.

## Security and data

No permission grants, hidden Binder calls or settings bypasses are introduced. Direct previews and preview controls do not write the selected Dream, its enabled state or timers. Cross-package, disabled and protected activities are rejected. Approved Plex credentials and device-local equipment identity are untouched.

## Verification and known limitations

The signed code 63 build passes the Java functional checks and 47 Python tests, with six device-dependent checks skipped. Actual API 28 picker navigation opened Cloud Drift Clock and Blue Meridian for 40 seconds each, displayed their scenes and returned with Back while the selected Black Screen and enabled state stayed unchanged. Aerial Views opened its TestActivity and returned, but its captured video area was black; that route check does not establish visible video playback. Jellyfish Drift V2 also had a black captured frame; its content visibility remains a separate check.

On code 62, all 25 reviewed direct routes opened and returned to the picker. All eight private-preview apps also reached their actual in-app preview controls. The selected screensaver, enabled state, launcher preferences, OS values, storage appops and Home/accessibility health were preserved. Contour Flow, Nebula Drift and Split-Flap Drift use their preview launchers rather than settings screens that lack a Preview button. AndroSaver's selected slideshow had no images; reaching that empty source is route proof, not proof that configured media played. The final layout-only code 63 also passed readable-label verification, a visible Blue preview and Contour controls/full-screen Preview/Back with state preserved. The current captures and completed native evidence are described in the [gallery](../screenshots.md) and [verification](../verification.md). Screensaver apps retain their own playback, codec and network requirements. An activity preview is not a bound system DreamService.

Automatic exact-item Plex handoff and saved-offset resume remain unfinished. This preview fix does not change that interoperability work or establish new-episode caption behavior.
