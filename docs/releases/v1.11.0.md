# Fire TV UI 1.11.0

Add Nibbles HD to the reviewed screensaver catalog and preserve individual Home
choices during APK replacement and settings repair. This minor release also adds
a narrow, protected Home preference contract for computer clients.

## Upgrade guide

Update 1.10.1 in place through Settings > Advanced > Updates, or verify the
published signed APK and use the installer from this release:

```sh
shasum -a 256 -c fire-tv-ui-1.11.0.apk.sha256
python3 scripts/install.py --serial YOUR_TV_IP:5555 --apk /path/to/fire-tv-ui-1.11.0.apk
```

Older same-signer 1.x installations can use the same installer. It grants the
normal setup access and copies the shared icons. Code 69's native receiver and
repair preserve the saved Home choices; the installer no longer sends the full
Home-on setting operation during an update. Do not uninstall or clear app data.
Existing layout, cards, custom icons, encrypted connections and other settings
remain in place. Android 8.1/API 27, target SDK 36 and the production signer are
unchanged. Keep a backup before deliberate recovery. Android normally rejects a
lower version code, so use a newer signed repair build rather than removing an
installation and its encrypted connections.

A host update does not install, select or replace a screensaver automatically.
Use the catalog or installed-app update screen when you choose to install
Nibbles. Its eight settings remain owned by the screensaver app.

## Breaking changes and compatibility

No settings migration or Android minimum change is required. The protected
`home-preference-on` and `home-preference-off` operations now write only the
Home-enabled preference. A computer client that deliberately wants the ordinary
coupled startup and routing choices must use `home-on` or `home-off` after
verifying its OS route. Code 69 adds `home-preference-state` and
`home-preference-clear` so clients can restore an absent key exactly. Require
code 69 or newer for this preservation contract; it is not provided by code 68.
See [computer Home transactions](../updates.md#computer-home-transactions).

An ordinary first Main launch still initializes missing defaults. The update
and narrow-API missing-key checks were completed before that initialization.
Explicit user Home on/off and the existing boot policy retain their behavior.

## Major changes

- Add the verified public Nibbles HD 1.0.0 APK as the 35th catalog entry, retaining
  every prior entry and default.
- Show its real physical gameplay thumbnail and open its declared native Preview.
- Include the original-work notice and complete Apache 2.0 license in the offline
  Preview media credits reader.
- Rebind enabled Home routing on package replacement and settings repair without
  normalizing startup, Home override or improved detection preferences.

## Minor changes and fixes

- Preserve all four Home values and key presence if a full native Home operation
  fails while writing accessibility routing.
- Report failure if a narrow Home preference commit is rejected.
- Remove the computer installer's redundant full Home-on call during replacement.
- Add functional native build CI, actual-source Home regression checks and
  installer rejection coverage.

## Security and data integrity

No new APK permission, library, network destination or background service is
introduced. The existing receiver requires DUMP permission. New operations
read or write only the Home-enabled preference, while full Home changes retain
readback and rollback. Nibbles itself runs offline with no requested permissions;
the launcher retains its existing user-initiated online features.

## Verification and known limits

The local suite passes 55 Python cases: 49 executed and six explicitly skipped
native opt-in checks, plus the standalone Java checks. The new JVM harness
executes the actual HomeControl, package receiver and protected receiver. It
proves mixed and missing preferences, readback failures at each Home write,
ordinary explicit controls and the unchanged boot policy. The previous package
receiver fails the mixed-preference regression.

The exact signed code 69 APK passed an actual code 68 replacement on the TV
emulator at native 1920x1080. Mixed Home values and a missing override key survived
before Main initialized. Both native Home services rebound. Narrow state/on/off/
clear and ordinary full on/off passed. After revoking the temporary secure-settings
permission, full on/off reported SecurityException and restored all four prior
values and key presence while leaving OS accessibility unchanged.

Native D-pad traversal observed all 35 catalog entries. Nibbles Preview and Back,
its declared settings activity and offline notice/license scrolling passed.
Slot remained selected, so the selected-saver Settings button was not switched
to Nibbles during this gate. All 14 UI preferences, 19 OS values, 34 APK identities,
readable providers, grants, appops, external files, preview caches and stopped
states were restored apart from the intended stopped UI 69 upgrade. The temporary
fixture was removed and permission revoked; final raw permission flags match the
baseline. See [verification](../verification.md) and the [native gallery](../screenshots.md).

These emulator results do not establish physical Fire OS Home or hardware-remote
behavior, new Dream binding, universal frame rates or thermal performance.
Existing physical feature evidence remains separately labeled by release.
Automatic external Plex playback and saved-offset resume are unchanged and are
not claimed complete by this release.
