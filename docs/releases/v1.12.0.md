# Fire TV UI 1.12.0

Add eight animated menu backgrounds, bringing the choice to twelve styles plus Off. A chosen background now follows supported Fire TV UI panels as well as Home. This compatible feature release also stops swallowing Home-up events when the cached launcher cannot be opened.

## Upgrade guide

Update an existing same-signer 1.x installation through **Settings > Advanced > Updates**, then confirm the normal Android replacement. Alternatively, verify the published APK and use the repository installer:

```sh
shasum -a 256 -c fire-tv-ui-1.12.0.apk.sha256
python3 scripts/install.py --serial YOUR_TV_IP:5555 --apk /path/to/fire-tv-ui-1.12.0.apk
```

Do not uninstall or clear app data. Existing app order, cards, hidden items, feed order, custom icons, authorized encrypted connections, Home choices and screensaver settings remain in place. There is no settings migration. Keep a backup before deliberate recovery. Android normally refuses a lower version code; use a newer signed repair build rather than deleting app data to roll back.

Animation remains opt-in. Open **Settings > Animated backgrounds** to select a style, speed, intensity and brightness. Off keeps your existing wallpaper. If you already chose a background, its choice and controls are retained.

The 32 shared input/app icons remain a separate image pack. APK-only native updates do not copy that pack. Use the matching release's icon ZIP, the repository icon installer or the paired APK-and-icons path in Fire TV Toolkit. Back up customized shared image files before deliberately replacing them. [Icon installation](../icons.md) explains the destination and image-picker indexing.

## Breaking changes and compatibility

None. The minimum remains Android 8.1/API 27, with target SDK 36. Package identity, production signer, requested permissions and all 36 screensaver catalog entries remain unchanged. No dependency, tracking or new storage-access grant is added.

This is a minor release because it adds compatible background choices. Background preference keys and their existing values are retained, as are the four saved Home preference values and their presence during an update.

## Major changes

- Add Flowing silk, Soft bokeh, Drifting stars, Warm embers, Ocean ribbons, Gentle rain, Orbital arcs and Light rays alongside the existing four styles.
- Show the chosen animation behind supported Fire TV UI panels, with a live preview and remote-friendly controls. Individual views stop their frame callbacks when hidden, paused or detached.
- Keep speed at 25/50/100%, and intensity and brightness at 25/50/75/100%. All controls stay in portable backups; Off restores the prior wallpaper.

## Minor changes and fixes

- Preserve the exact cached explicit launcher intent and its flags for successful hardware Home dispatch.
- Leave Home-up unconsumed when that intent is unavailable or launching it throws, so the system fallback remains available. Static dispatch/result diagnostics omit intent data and exception messages.
- Notify the existing package-pinned preference receiver after a successful backup restore, so connected Home controls reload restored choices. Invalid data or a failed save sends no notification. A notification delivery failure does not undo successfully saved settings.
- Keep unrelated keys and non-up Home behavior unchanged. This source correction does not establish the cause or resolution of the reported Calvin hardware Home failure.

## Verification and limits

The physical Fire TV API 30 background check selected all 12 animated styles with the D-pad and verified their saved values. Speed, intensity and brightness 100 were exercised separately. Three approved final signed APK settings images at 1920x1080 on the API 34 TV emulator appear in the [native gallery](../screenshots.md#fire-tv-ui-1120-code-71), with full source and capture hashes. No personal Home cards or library history are included.

Those captures use exact final signed APK `4e992411`. Its six background sources and 14 compiled background class payloads match the separately tested initial physical candidate byte for byte; both Home corrections are included in the final release. The Home helper passed observable success, null-target, launch-failure, disabled, other-key and action tests, plus the built Hra bytecode-hook check and required native-build CI. These source tests do not prove delivery of an actual hardware Home press on Calvin.

The initial background candidate also reached the ordinary selected Aerial Dream at 301.296 seconds with unchanged input timestamps and the original 300000ms delay. A stable 3-second Dream observation recorded zero UI presents. Strict cleanup restored all 51 portable UI preferences, 61 protected package/UID identities, 19 OS values, grants/appops and external backup/import bytes. The combined build retains 14 background JVM class payloads byte for byte; this is not an exact combined APK hardware Home pass. See the detailed [verification record](../verification.md#fire-tv-ui-1120-version-code-71).

The final unsigned build and all six Java suites passed; the Python suite passed 59 cases, with 53 executed and six native-only skips. Restore-notification regression tests failed on the previous implementation and passed with notification after commit, including invalid-data, failed-commit and notification-delivery failure behavior.

The exact final signed APK passed an API 34 native cache-refresh check through real backup restores: true-to-false-to-true improved Home detection changed the Hra event mode in both directions while keeping the same process and service binding. This is not physical remote Home delivery proof.

The existing README banners are unchanged; prior full theme/width/reduced-motion proof remains applicable to those bytes. Final release artifacts, required CI and primary-branch payload verification are recorded with the published release. The [verification guide](../verification.md#fire-tv-ui-1120-version-code-71) distinguishes current native observations from earlier checks and remaining hardware limitations.

Automatic exact-item playback/resume through the installed Plex household picker remains unverified. The native UI companion-icon copy feature is not included. This release makes no new screensaver visual-quality, thermal-duration or universal performance claim.
