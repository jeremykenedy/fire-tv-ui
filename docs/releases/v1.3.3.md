# Fire TV UI 1.3.3

Fire TV UI 1.3.3 fixes launcher idle activation opening Aerial Views when another TV screensaver was selected. The launcher now follows the TV's selection and preserves the existing launcher idle switch and timers.

## Upgrade guide

Install the signed `fire-tv-ui-1.3.3.apk` over an existing 1.x installation after verifying its SHA-256 sidecar. Android 8.1 / API 27 remains the minimum. The package and signing key remain unchanged. Layouts, icons, selected screensaver, enabled state and timer choices are preserved. No reset or migration is required.

The Appearance option is now labeled **Launcher idle screensaver**. When enabled, it attempts the selected TV screensaver after 90 seconds of launcher inactivity. Android 8.1 through 13 uses the system's screensaver starter. Android 14 and later uses a reviewed, exported preview activity for the selected app when available. An unsupported selection leaves system idle handling active; it does not open another app or a launcher clock.

## Breaking changes

None. The launcher idle option now honors the selected TV screensaver instead of opening a fixed Aerial Views preview.

## Major changes

None. This is a correction to existing idle behavior.

## Minor changes and fixes

- Read the current selected DreamService at idle activation.
- Restrict preview fallback to an exact reviewed DreamService and an activity in the same package.
- Preserve normal focus restoration and reset the idle attempt timer without changing the saved idle switch.
- Pin Twilight Hearth 1.1.0 and refresh its bundled sample from the corresponding physical Fire TV capture.

## Verification

The signed candidate is version 1.3.3/code 37 with the existing production certificate. The build and host checks pass, including 15 focused idle dispatch cases, 38 screensaver checks, 17 input checks, diagnostics and storage parsing checks, and 16 Python tests. Four separately configured native tests are explicitly skipped in the host run. GitGuardian passes on the draft source pull request; this private repository has no Actions workflow.

The recovered candidate `027c88d2223fa60a48a86e38f67c9d6d7ef3d77b3bc8a93de57fa2b240d56717` passed fresh Android TV API 34 observations at 1920x1080. Slot Vision opened its actual preview after 95.3 seconds of launcher inactivity. An unsupported Aquarium 4K selection remained in the launcher for 95.3 seconds without opening Aerial Views or a launcher clock. The original private idle switch, guarded selection and five system values were restored. Physical Fire TV selected-Dream binding and restoration remain release gates.

## Security and data integrity

This patch adds no permissions, hidden Android calls, remote services or automatic permission grants. Idle activation does not change the selected component, enabled state or timer settings.

## Rollback

Android blocks installing a lower version code over this release. Save a TV backup before uninstalling, then install the previous signed APK and restore the backup. Screensaver apps remain installed independently of Fire TV UI.

## Known limitations

Android 14's system starter activity no longer starts dreams. Explicit previews are reviewed for Slot Vision, Hearth Presence and Rainforest Cascade. Other apps, including Aquarium 4K, retain Android's own idle handling on Android 14 and later. A preview activity is not proof that a DreamService is bound.
