# Fire TV UI 1.11.1

Add the verified Lumen Breaker release to the screensaver catalog with its actual
native thumbnail and bundled offline notices. This catalog patch keeps both
launcher DEX files byte-identical to public 1.11.0.

## Upgrade guide

Update 1.11.0 in place through Settings > Advanced > Updates, or verify the
published signed APK and use the installer from this release:

```sh
shasum -a 256 -c fire-tv-ui-1.11.1.apk.sha256
python3 scripts/install.py --serial YOUR_TV_IP:5555 --apk /path/to/fire-tv-ui-1.11.1.apk
```

Older same-signer 1.x installations can use the same installer. It grants normal
setup access and copies the shared icons. Do not uninstall or clear app data.
Keep the existing layout, cards, custom icons, encrypted connections and
screensaver settings. The code 69 Home preference and replacement-preservation
behavior is unchanged. Keep a backup before deliberate recovery. Android
normally refuses a lower version code; use a newer signed repair build rather
than deleting app data to roll back.

A host update does not install or select a screensaver automatically. Choose
Lumen in the installation catalog when wanted. Its settings remain owned by
Lumen Breaker.

## Breaking changes and compatibility

None. Android minimum 8.1/API 27, target SDK 36, package identity, production
signer, requested permissions, Home API, default choices and all 35 prior catalog
entries remain unchanged. There is no settings migration or new dependency.
This release adds catalog data and attribution without changing menu animation,
Home routing or screensaver execution code.

## Major changes

- Add [Lumen Breaker 1.0.0](https://github.com/jeremykenedy/lumen-breaker/releases/tag/v1.0.0)
  as entry 36 with its exact signed APK identity, published checksum and native
  PreviewActivity. Its real code 3 capture supplies the 384x216 picker image.
- Include the complete Apache 2.0 license and original-work notice in the
  existing offline preview-media reader.

## Minor changes and fixes

- Retain every earlier catalog row, preview mapping, setting and runtime class.
- Record source capture, checksum, declared settings route and provider schema
  provenance with the new entry.

## Verification and limits

The source passes the Java functional checks and 56 Python cases, with 50
executed and six native-only cases skipped in the local environment. The new
catalog contract checks the public Lumen APK pin, settings and preview routes,
image provenance and included notices. Both DEX payloads match public code 69.
The exact signed code 70 passed an actual same-signer update on the API 34 TV
emulator. Native catalog entry 36, the full thumbnail, 40-second app Preview,
Back, declared settings and the complete offline notice passed. The native
TextView matched the bundled 11,358-character Apache body exactly; not every
license page was visually read. A poorly framed license-header image is excluded.
All 14 UI preferences, 19 protected OS values, 34 APK identities, readable
providers, grants, UID/appops modes, external files and stopped states were
restored apart from the intended stopped UI 70. Final state was Google Home
awake, no Dream, no bound accessibility service and the guard stopped. The
[native gallery](../screenshots.md) records the five approved raw captures.
Functional CI builds the unsigned native APK and checks the source and artifacts.

This data update adds no new physical Home, Dream binding, performance or
hardware compatibility claim. Lumen's own release documents its separate
physical gameplay and normal-idle Dream checks. User confirmation remains
required for ordinary on-TV package replacement.
